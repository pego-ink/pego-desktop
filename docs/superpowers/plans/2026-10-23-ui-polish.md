# UI polish skill and polish checks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An always-on `ui-polish` design skill plus five polish checks in `check_layout`, so agents both know the
polish rules and see polish defects while verifying.

**Architecture:** `ui-polish` is a second skill with `core: true`; a new `coreSkills()` puts every core skill at
the front of each run and the prompts name it next to `core`. The checks live in a new pure module
`inspect/check-polish.ts`, which `checkLayout` calls per node and de-duplicates per component source node.

**Tech Stack:** TypeScript (strict, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`), Bun test, Zod-typed
documents from `@pego/doc`.

**Spec:** `docs/superpowers/specs/2026-10-23-ui-polish-design.md` (read it first; section numbers below refer to
it).

## Global Constraints

- Work on a local branch `feat/ui-polish` cut from `dev`. Local commits only; never push, never open a PR.
- Never stage the user's design work: `design/pego-website/project.pego`, `design/ig-post/`, `design/we-ui/`.
- Commit messages: Conventional Commits with a scope, ending with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Run `bun run format` before each commit.
- Do not touch `packages/doc/src/schema.ts`, `packages/doc/src/ops.ts`, `packages/agent/src/tools.ts`, root
  `package.json`, `skills/system/core.ts`, `skills/system/dashboard.ts`, `styles/presets.ts`.
- `ui-polish` content: English, no em dash (`—`), only Pego props and tools, 2000 to 3300 bytes (same bound as
  `core`), checklist of 6 to 8 items.
- System prompt strings stay constant; never interpolate per-run values into them.
- Polish checks are conservative: when a case is ambiguous, report nothing (spec anti-goal "false positives").
- Before calling the work done: `bun run typecheck`, `bun run lint`, `bun run test` all pass.

## Review Focus

- Radii and paddings written as `$variables` (we-ui uses `$radius-lg`, `$space-*`) must resolve; reading raw
  props would silently skip the very documents agents produce. Test in Task 4.
- A pill radius such as `999` counts as half the smaller side; a pill inside a pill with a matching inset is
  concentric and must give no issue. Test in Task 4.
- Hidden children (`visible: false`) and zero-size boxes have no layout box and are ignored by every polish
  check, including as an icon's neighbour. Test in Task 5.
- A row whose cards are instances (`ref`) is judged on the resolved instance, and a row that already uses
  `height: "fill_container"` gives nothing. Test in Task 5.
- A vertical stack of cards with different heights is never reported by the row check. Test in Task 5.

### Task 4: Polish module, de-duplication and the two corner checks

**Files:**
- Create: `packages/agent/src/inspect/check-polish.ts`
- Modify: `packages/agent/src/inspect/check-layout.ts` (`Context`, `checkNode`, `checkLayout`)
- Test: `packages/agent/src/inspect/inspect.test.ts` (new `describe("check_layout polish")`)

**Interfaces:**
- Produces:
  - `type PolishIssue = { key: string; severity: Severity; node: PegoNode; issue: string; hint: string }`
  - `checkPolish(doc: PegoDocument, layout: Layout, node: PegoNode, source: string): PolishIssue[]`: findings
    for one expanded node (a frame and its direct children); `[]` for anything else. `source` is the node's
    stable source id (see below).
  - `sourceId(id: string): string`: the part of a render id after the last `/` (`"inst/rowChip"` → `"rowChip"`).
  - Stable source id: for a `ref` it is the component id (`ref.ref`), because an instance root keeps the ref's
    own id; for anything else it is `sourceId(id)`. `walk` in `check-layout.ts` computes it for the node it
    visits and passes it through `checkNode`; `checkPolish` computes it the same way for children it resolves.
  - Keys: `corner:<parent>:<child>`, `icon:<icon>`, `row:<frame>`, `padding:<frame>`, each with stable source
    ids, so a reusable `user` and its instances `u1`, `u2` all give `corner:user:avatar`.
- Consumes from `@pego/doc`: `resolveNumber`, `resolveSides` (padding as `[t, r, b, l]`), `resolveInstance`,
  `type Layout`. `Severity` comes from `check-layout.ts` as `import type`.

Shared rules for every check in this module: resolve `ref` children with `resolveInstance` (skip `null`); skip
any node without a layout box or with a zero width or height; read every number through `resolveNumber` so
`$variables` work; effective radius = `min(cornerRadius, width / 2, height / 2)`.

`ref(id, refId, props)` next to `frame`/`rect`/`text`. Then, with `polish = (issues) => issues.filter(i =>

- "variables resolve": the `user` case with `cornerRadius: "$r-sm"`, `padding: "$s-sm"` and variables

- [ ] **Step 3: Implement the module and the corner checks**

Corner checks run for a `frame` with `layout` horizontal or vertical and effective radius `rp > 0`. Inner box =
the frame's box inset by its padding. For each visible child with a `cornerRadius` prop and effective radius
`rc > 0`, find the first inner corner it touches (both child edges within 0.5px of the inner box edges) whose
two paddings are equal (within 0.5) and ≤ 24; call that padding `p`. Let `sw` be the frame's stroke width when the
stroke is uniform (number, or `1` when `width` is unset; `0` for no stroke or per-side widths), and
`expected = rc + p + sw`.
- `rc > rp + 0.5` → `warning` on the frame: issue names the child and both radii and contains "rounder than";
  hint gives `expected` and the alternative of a smaller child radius.
- otherwise `|rp - expected| > 2` → `info` on the frame: issue contains "not concentric"; hint gives `expected`.

- [ ] **Step 4: Wire it into `checkLayout`**

`Context` gets `polishSeen: Set<string>`; `checkNode` gets a `source: string` parameter from `walk`. In
`checkNode`, right before `if (!isContainer(node)) return;`, call `checkPolish(doc, layout, node, source)` and,
for each finding whose `key` is not in `polishSeen`, add the key and
`report(ctx, severity, issue.node, issue.issue, issue.hint + (issue.node.id.includes("/") ? INSTANCE_HINT : ""))`.
